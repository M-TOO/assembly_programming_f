# Analysis of Stack Operations

## This demonstrates function calls, stack frames, and local variable storage in 64-bit NASM assembly system.

## Program Flow
At the start RSP points to the top of the stack.

1. Call work pushes the 8-byte return address onto the stack. RSP decrements by 8 bytes.
2. Push RBP saves the caller's base pointer onto the stack. RSP decrements by 8 bytes.
3. MOV RBP, RSP establishes the new stack frame base.
4. SUB RSP, 16 decrements RSP by 16 bytes to allocate space for local variables.
   - Value 100 is stored at [RBP - 8].
   - Value 200 is stored at [RBP - 16].
   - Values are loaded back into RAX and RBX.
**RSP is now 32 bytes lower than what it was at the start.**
5. MOV RSP, RBP restores RSP to clean up the 16 bytes of local variable space.
6. Pop RBP restores the old base pointer. RSP increments by 8 bytes.
7. RET pops the return address into RIP (RSP increments by 8 bytes) and control returns to main execution.
The program exits.

The stack is used to maintain procedure scope and reserve memory for local variables. Using RBP to mark the frame base allows easy variable access, and resetting RSP to RBP ensures proper stack cleanup before returning.
